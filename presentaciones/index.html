Transición. Diga solo esto: un tipo de dato abstracto no es una clase. Es una promesa. Qué valores existen y qué operaciones están permitidas. Cómo se guarda por dentro queda escondido a propósito. Baje para ver el contrato de la pila y de la cola.

1.1.1 · Contrato

El TDA define el contrato

Pila

LIFO

push pop peek

Sale primero el último elemento añadido.

Cola

FIFO

enqueue dequeue

Sale primero el elemento más antiguo.

La abstracción permite cambiar la representación interna sin cambiar el código cliente que depende del contrato.

Presente las dos tarjetas por separado. En la pila, marque LIFO con un ejemplo de deshacer: la última edición es la primera que se revierte. En la cola, marque FIFO con una fila de impresión: lo que llegó primero se atiende primero. Cierre con la frase de abajo: si el cliente solo usa push y pop, mañana la pila puede dejar de ser un arreglo y el cliente no se entera. No abra todavía el código. 1.1.1 · Encapsulación

Una pila que no expone su arreglo

class Pila {
  #elementos = [];

  push(valor) {
    this.#elementos.push(valor);
  }

  pop() {
    return this.#elementos.pop();
  }

  peek() {
    return this.#elementos.at(-1);
  }

  get longitud() {
    return this.#elementos.length;
  }
}

Campo privado

#elementos no se lee desde fuera de la clase.

Operaciones

El cliente empuja y saca. No indexa el arreglo.

edición pop() devuelve el último push
Recorra el código en tres pasos, que ya están marcados como fragmentos de línea. Primero el campo: el numeral hace privado a elementos, así que historial.elementos o historial['#elementos'] no son la API. Segundo, push y pop modifican el tope. Tercero, peek y longitud observan sin sacar. Arme el ejemplo en voz alta: push de inicio, push de edición, pop devuelve edición. Si alguien pregunta por el arreglo, responda que esa pregunta ya rompió el contrato.

1.1.1 · Forma

El contrato no exige la palabra class

  • JavaScript no declara interface. TypeScript sí, y solo en compilación.
  • El código cliente depende de la forma: métodos y comportamiento. Es duck typing.
  • Una clase ES6 construye objetos. No es el único modo de cumplir el contrato.
  • Pruebe las operaciones públicas. La invariante vive dentro del TDA.
function guardarTodo(almacen, valores) {
  for (const valor of valores) almacen.guardar(valor);
}

const memoria = { datos: [], guardar(valor) { this.datos.push(valor); } };
guardarTodo(memoria, ["A", "B"]);
Lea la función guardarTodo antes de mostrar el objeto. Pregunte: ¿qué necesita almacen para que esto no reviente? Solo un método guardar. Entonces muestre el objeto literal: no hay class, y aun así el contrato se cumple. El resultado es el arreglo A, B dentro de datos. Cierre advirtiendo que datos quedó público en este ejemplo mínimo: en un TDA de verdad esa lista sería privada y el test miraría guardar, no el arreglo. Referencia para quien quiera leer después: campos privados en MDN.

Cambie de bloque. Diga: hasta aquí el contrato. Ahora, qué ocurre en la asignación. Hay dos ideas que se confunden en clase: copiar un valor y compartir un objeto. Baje. La frase stack para primitivos y heap para objetos va a aparecer, y hay que decir que es un modelo didáctico, no una regla de ECMAScript.

1.1.2 · Modelo

Qué se copia al asignar

Primitivos

Se copia el valor

number boolean bigint string symbol undefined null

Objetos

Se copia la referencia

Dos variables pueden nombrar el mismo objeto. El argumento también viaja por valor: si ese valor es una referencia, ambos ven el mismo objeto.

Stack y heap, aquí, son un dibujo para pensar. El motor puede representar las cosas de otro modo.

Izquierda: asigne un número, cámbielo en la copia y muestre que el original no se mueve. Derecha: asigne un objeto a otra variable, mute un campo y muestre que ambas lo ven. Remarque que el parámetro de una función recibe una copia del valor de la variable. Si ese valor es una referencia, no se clonó el objeto. La frase en rojo es obligatoria: no prometan que el número vive en el stack físico. El recolector libera objetos que ya nadie puede alcanzar. Siguiente slide: cómo medir, sin convertir esa medida en un precio por objeto.

Este fragmento es Node, no el navegador. Léalo en tres tiempos. Primero se toma heapUsed. Después se retienen un cuarto de millón de objetos, porque si no guardamos el arreglo la medición no tiene sentido. Al final se vuelve a leer el proceso. Las tres tarjetas no son el tamaño de un registro: heapUsed y heapTotal hablan del heap de V8, rss incluye más que ese heap. Diga explícitamente que una resta no entrega bytes por objeto. La recolección y el resto del proceso mueven el número.

1.1.2 · Lectura

Cómo no mentirse con una resta

heapUsed / heapTotal

Usado y asignado dentro del heap de V8.

external / arrayBuffers

Memoria fuera de los objetos JavaScript, buffers incluidos.

rss

Todo el proceso. Siempre es más que el heap.

Compare varias muestras en las mismas condiciones. En Chrome, dos heap snapshots y el panel Retainers.

No repita la tabla como lista. Una tarjeta, una decisión. Si el número que crece es external o arrayBuffers, no busquen el objeto JavaScript: busquen el buffer. Si crece rss y el heap no, el costo está en otra parte del proceso. Para el navegador, el camino es DevTools: snapshot antes, snapshot después, y Retainers para ver quién sigue apuntando al objeto. Cierre el bloque recordando el argumento: no hay una regla especial de pase por referencia. Se copia el valor, y a veces ese valor es una dirección.

1.2.1 · Elección

Cinco representaciones, una operación dominante

Array

Secuencia ordenada. Índice, longitud dinámica, métodos de colección.

TypedArray

Números sobre un ArrayBuffer. Longitud fija. No guarda objetos.

Set

Un valor, una vez. Igualdad SameValueZero.

Map

Clave de cualquier tipo. Conserva el orden de inserción.

Registro

Objeto con campos nombrados. Claves string o symbol.

Destape una tarjeta y dé un ejemplo de una sola frase. Array: la lista de cursos, porque el orden de la malla importa. TypedArray: una muestra de audio o un pixel, no un estudiante. Set: etiquetas, porque obligatoria repetida sigue siendo una. Map: estudiantes por id numérico, sin convertir la clave a string. Registro: el estudiante en sí, con nombre y activo. Si preguntan por la complejidad, diga que la especificación no les firma un big-O por método: eso se mide en el motor que van a usar.

1.2.1 · Criterio

Elija por la operación, después mida

  • Array cuando importan el orden, el recorrido y las operaciones de secuencia.
  • Set para unicidad y pertenencia. Map cuando la clave no es un string o el conjunto de entradas cambia.
  • TypedArray para datos numéricos empaquetados: imagen, audio, protocolo. No almacena objetos arbitrarios.
  • No copie la colección en cada paso. En datos grandes, la copia también cuesta.
Esta slide es la regla de diseño, no un resumen. Pida que elijan en voz alta una estructura para tres casos rápidos: historial de navegación, diccionario de sesiones por objeto usuario, y buffer de un archivo binario. El último punto, en rojo, es el que más se viola en los trabajos: Array.from dentro de un ciclo, o convertir un Set a arreglo para volver a preguntar si contiene. Midan con datos parecidos a los reales y en el motor de destino. Referencia: TypedArray en MDN.

Archivos

Estructura de Datos

Salimos de la memoria del proceso y entramos al disco. Dos patrones, y la diferencia no es de estilo: es de cuánta información hace falta antes de leer. El stream sirve cuando se procesa el archivo completo por bloques. El offset sirve cuando ya saben en qué byte está el registro. Adelanten que el offset es en bytes, no en caracteres. En UTF-8 un carácter puede ocupar varios bytes.

1.2.2 · Patrones

Dos lecturas, dos preguntas

Secuencial

createReadStream()

El archivo se recorre por bloques. Conviene cuando hay que procesarlo completo y no quieren cargarlo de una vez.

Posicional

open() + read(position)

Hace falta conocer el offset en bytes del registro. Un formato de longitud fija puede calcular cabecera + i * tamaño.

Haga la pregunta antes de mostrar la segunda tarjeta: si el registro que buscan es el número mil, ¿leen los 999 anteriores? Si el formato es de longitud fija, no. Si es texto de líneas irregulares, el stream o un índice previo siguen siendo el camino. Repita: position cuenta bytes. Al final del archivo, bytesRead puede ser menor que el buffer que reservaron. Eso se ve en el código de la siguiente slide.

1.2.2 · Código

Stream completo, luego 16 bytes en el offset 128

const { createReadStream, promises: fs } = require("node:fs");

async function main() {
  const ruta = process.argv[2] ?? "contenido.md";
  for await (const fragmento of createReadStream(ruta, { encoding: "utf8" })) {
    process.stdout.write(fragmento);
  }

  const archivo = await fs.open(ruta, "r");
  try {
    const buffer = Buffer.alloc(16);
    const { bytesRead } = await archivo.read(buffer, 0, buffer.length, 128);
    console.log("\nBytes desde offset 128:", buffer.subarray(0, bytesRead));
  } finally {
    await archivo.close();
  }
}
Primero el for await: cada fragmento se escribe y se puede descartar. Si lo concatenan todo en un string, perdieron la ventaja del stream. Después el acceso directo: se abre el archivo, se reserva un buffer de 16 bytes y se lee desde el byte 128. subarray hasta bytesRead evita imprimir ceros de más cuando el archivo es corto. El finally cierra el handle aunque la lectura falle. Dígales que este archivo se correría con node, pasándole la ruta. No lo ejecuten dentro de la diapositiva.

1.2.2 · Diseño

El índice y el archivo tienen que ponerse de acuerdo

  • Si el consumidor no acumula fragmentos, la memoria no crece con el tamaño del archivo.
  • El acceso aleatorio paga cuando hay índice, cabecera o registros de longitud fija.
  • En UTF-8 calculen offsets con la codificación, no con el número de caracteres.
  • Comprueben bytesRead. Si hay escritores concurrentes, definan cómo se mantiene el índice.
El punto que hay que dejar clavado es el último. Un offset calculado contra un archivo que otro proceso está agrandando o truncando no es una lectura: es una condición de carrera. No hace falta resolverla hoy. Sí hace falta que el diseño diga quién actualiza el índice. Repita bytesRead con un archivo de 10 bytes y un offset de 128: la lectura no lanza por estar cerca del final, devuelve menos bytes. Referencia: FileHandle.read y streams en la documentación de Node.

Persistencia

Estructura de Datos

Último bloque. La pregunta ya no es cómo recorrer un archivo, sino dónde vive el dato cuando el proceso termina. Hay cuatro medios en esta sesión: JSON, binario, localStorage e IndexedDB. Ninguno del navegador reemplaza una copia en el servidor. Baje y elija el medio antes de mostrar la API.

1.2.3 · Medio

Dónde guardarlo cambia el costo de leerlo

JSON

Texto interoperable

Al parsear, el documento entero se materializa. BigInt no entra directo.

Binario

Bytes con esquema

Controlan tamaño y orden. Hace falta versión del formato.

localStorage

Strings por origen

API síncrona. Sirve para preferencias pequeñas.

IndexedDB

Registros e índices

Asíncrono, con transacciones. No es un backup del servidor.

Cuatro medios, cuatro límites. JSON se lee fácil y se paga completo al parsear. El binario exige que ustedes documenten el esquema: en el ejemplo que viene, un entero de 32 bits little-endian. localStorage bloquea el hilo y solo acepta strings: un objeto pasa por JSON.stringify. IndexedDB es el que aguanta una colección con consultas, y aun así vive en el navegador de esa persona, en ese origen. Validar al leer: permisos, cuota y formato roto son los tres errores que el trabajo tiene que nombrar.

1.2.3 · Node

Un JSON legible y un entero de 4 bytes

const { readFile, writeFile } = require("node:fs/promises");

async function main() {
  const estudiantes = [{ id: 42, nombre: "Ana" }];
  await writeFile("estudiantes.json", JSON.stringify(estudiantes, null, 2));
  const recuperados = JSON.parse(await readFile("estudiantes.json", "utf8"));

  const registro = Buffer.alloc(4);
  registro.writeUInt32LE(2026, 0);
  await writeFile("anio.bin", registro);
  const bytes = await readFile("anio.bin");
}
Ana recuperados[0].nombre
2026 bytes.readUInt32LE(0)

Mismo número, dos formatos. El binario no se abre en un editor para entenderlo.

Partan el código en dos. El JSON guarda un arreglo con Ana y lo vuelve a parsear: el nombre sobrevive porque es un tipo que JSON conoce. Después, cuatro bytes y writeUInt32LE escriben 2026 en orden little-endian. readUInt32LE lo recupera. Pregunte qué pasaría con un BigInt o con una función dentro del objeto: JSON.stringify no los conserva. El archivo anio.bin sin el esquema es indistinguishable de ruido. Por eso el formato necesita versión.

1.2.3 · Navegador

Preferencia pequeña, colección con transacción

localStorage.setItem("preferencias", JSON.stringify({ tema: "claro" }));
const preferencias = JSON.parse(localStorage.getItem("preferencias") ?? "{}");

const solicitud = indexedDB.open("unl-demo", 1);
solicitud.onupgradeneeded = () => {
  solicitud.result.createObjectStore("ajustes", { keyPath: "id" });
};
solicitud.onsuccess = () => {
  const db = solicitud.result;
  const tx = db.transaction("ajustes", "readwrite");
  tx.objectStore("ajustes").put({ id: "tema", valor: preferencias.tema });
  tx.oncomplete = () => db.close();
};

localStorage es sincrónico y estrecho. IndexedDB agrupa el cambio en una transacción. Ninguno sustituye la copia del servidor.

Señalen el stringify: sin eso, localStorage guarda el string objeto Object. El operador de fusión cubre la primera visita, cuando la clave no existe. En IndexedDB, onupgradeneeded crea el almacén solo cuando cambia la versión. El put va dentro de una transacción readwrite, y el close espera a oncomplete, no al return de put. Si queda tiempo, pregunte por qué sería un error guardar ahí la nómina de la universidad. Porque el dato vive en un navegador, sin el respaldo ni el control de acceso del servidor.
